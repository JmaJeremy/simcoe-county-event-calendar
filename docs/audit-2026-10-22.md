# Audit, 2026-10-22

Findings from a whole-repo audit, most important first. Tick each one off as it merges; open PRs are named beside their item.
Line numbers are as of `origin/main` at 903066e.

## Must fix

- [x] 1. **Stored XSS through private-use characters in a description.** `apps/web/src/markdown.ts` `unhide` turned every U+E000–U+E07F character back into ASCII, including ones a source sent, so U+E03C became a live `<`. Fix: replace those characters before escaping.
- [ ] 2. **A mail scanner can verify an attacker's account, and Google sign-in then links into it.** `auth/routes.ts` `/account/verify` consumes the token on GET; `auth/google.ts` links to any verified user. Fix: GET shows a confirm button, POST consumes. — PR #53
- [ ] 3. **A cluster split can give two events the same id; one vanishes every run.** `packages/core/src/dedup.ts` fallback `representative.id` is not checked against `used`. — PR #54
- [ ] 4. **Two manual events with no link always merge.** `urlMatch('' , '')` is 1. Return 0 when either is empty; bump `RULES_VERSION`. — PR #54
- [ ] 5. **A listing that reappears unchanged loses its enriched description, price and poster for good.** `reconcile.ts` sends `reactivated` through the full upsert. Write only `active`, `removed_at`, `status`, `last_seen_at`. — PR #54
- [ ] 6. **The session cookie dies at 30 days however active the reader is.** `auth/session.ts` `Max-Age` is `IDLE_DAYS`; use `ABSOLUTE_DAYS`. — PR #53
- [ ] 7. **Ten bad sign-ins lock the owner out of sign-in and reset.** `auth/routes.ts` reset uses the same throttle key; use `reset:${email}`. — PR #53
- [ ] 8. **Sign-in to an unverified account resends mail without limit**, enough to burn the daily mail quota. Skip when an unused verify token is under 15 minutes old. — PR #53
- [ ] 9. **A suggestion or news draft can be saved as an event twice.** `console.ts` `createEvent` never checks `handled_at`. — PR #55
- [ ] 10. **Municipality pages hide events running now.** `placeResponse` uses `local_date >= today`; use `buildQuery`'s `since` test. — PR #56
- [ ] 11. **Unfiltered `/calendar.ics` will start dropping future events at the 10,000 cap** (projected late January 2027). Default `since` to today minus 30 days. — PR #56
- [ ] 12. **"This weekend" / "Next 7 days" hide festivals already running.** `from` compares the start date; compare the end date, server and `app.js`. — PR #56
